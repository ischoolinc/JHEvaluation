# 匯入評量成績調整 1002

## 修改原因

匯入「平時評量」時，學生即使已修習該學年度、學期、課程，只要課程沒有 `RefAssessmentSetupID`，驗證仍會先報「無評量設定」，平時評量無法匯入。

本次只放寬「平時評量」的評量設定驗證。一般段考與其他評量的驗證、寫入方式都不改。

## 原本平時評量為何會被「無評量設定」擋住

`ValidateRow` 在確認學生有修課後，會進入「驗證評量是否存在」。原本流程是：

1. `attendCourse.RefAssessmentSetupID` 為空白 → 直接加入「無評量設定」。
2. 有評量設定，但 `courseAe` 找不到該設定 → 同樣加入「無評量設定」。
3. 有評量設定時，才比對系統 Exam 名稱。比對條件曾加上 `|| examName == "平時評量"`，所以「平時評量」只有在課程已有評量設定、且設定內至少有一筆存在於系統 Exam 的試別時，才不會被擋下。

因此課程沒有段考評量設定時，「平時評量」會在第 1 步就被「無評量設定」擋掉，進不了後續寫入。

## 修改的驗證條件

檔案：`ImportExport/ImportExamScore.cs`

在「驗證評量是否存在」外包一層：

```text
if (examName != "平時評量")
```

評量名稱為「平時評量」時，略過：

- `RefAssessmentSetupID` 是否為空白
- `courseAe` 是否包含該評量設定
- 系統 Exam 是否存在名稱為「平時評量」的試別

學生仍須通過既有的學生存在與修課檢查。通過後才進入原本的平時評量寫入（`OrdinarilyScore`、`OrdinarilyEffort`、`JHSCAttend.Update`）。

一般評量（第一次評量、第二次評量、第三次評量，以及其他非「平時評量」的名稱）仍依原本順序檢查：

```text
RefAssessmentSetupID → courseAe → Exam 名稱
```

一般評量比對 Exam 名稱時，已拿掉 `|| examName == "平時評量"`。該條件只存在於一般評量分支之外，拿掉後不會再讓「平時評量」這個名稱通過一般段考的 Exam 名稱比對。

## 未改動

- 學生是否存在
- 學年度、學期、課程名稱的修課檢查；沒有修課仍顯示「無修課記錄」
- RequiredFields 與其他匯入格式
- 平時評量寫入 `JHSCAttendRecord.OrdinarilyScore` / `OrdinarilyEffort`，以及 `JHSCAttend.Update(record)`
- 一般段考寫入 `JHSCETake` 的新增／更新
- 沒有「努力程度」欄位時，依分數轉換努力程度

## 測試案例與測試結果

此專案沒有可單獨執行 `ImportExamScore` 驗證的測試專案。以下依修改後的 `ValidateRow` 分支，對五個案例做程式路徑核對。

### Case 1：沒有評量設定 + 平時評量

條件：課程 `RefAssessmentSetupID` 為空白，評量名稱為「平時評量」，分數評量為 85，學生有修課。

結果：符合預期。`examName != "平時評量"` 不成立，略過評量設定驗證，不會加入「無評量設定」。後續寫入仍把分數寫入 `OrdinarilyScore`。

### Case 2：沒有評量設定 + 一般段考

條件：課程 `RefAssessmentSetupID` 為空白，評量名稱為「第一次評量」。

結果：符合預期。進入一般評量驗證，`RefAssessmentSetupID` 為空白時加入「無評量設定」，不可匯入。

### Case 3：有評量設定 + 正確段考名稱

條件：課程有評量設定，設定內有「第一次評量」，匯入評量名稱為「第一次評量」。

結果：符合預期。`courseAe` 中的 Exam 名稱與匯入名稱相同時，`examValid` 為 true，不加入錯誤，沿用原本匯入流程。

### Case 4：有評量設定 + 不存在的段考名稱

條件：課程有評量設定，設定內沒有「第四次評量」，匯入評量名稱為「第四次評量」。

結果：符合預期。比對不到 Exam 名稱時加入「評量名稱無效」，不可匯入。

### Case 5：沒有修課 + 平時評量

條件：學生沒有修習該課程，評量名稱為「平時評量」。

結果：符合預期。`attendCourse` 為 null 時，在進入評量設定驗證之前就加入「無修課記錄」。平時評量的放寬不會略過修課檢查。
