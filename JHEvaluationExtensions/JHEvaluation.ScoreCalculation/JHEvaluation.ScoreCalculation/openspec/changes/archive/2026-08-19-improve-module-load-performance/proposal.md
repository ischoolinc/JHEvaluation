## Why

目前模組載入時在 UI 執行緒同步完成部署模式判定、功能選單、權限、明細元件及資料合理性檢查註冊，但缺少分段耗時量測與可重複的效能基準，因此無法確認真正瓶頸，也容易在調整初始化流程時造成選單、權限或事件遺漏。需要建立可觀測、可驗證的載入流程，並將非首屏必要工作移出關鍵路徑，以縮短使用者等待時間。

## What Changes

- 建立模組載入效能基準，分段記錄部署參數、UI 功能註冊、權限設定、明細元件及資料合理性檢查的耗時與總耗時。
- 依量測結果辨識主要瓶頸，將非必要的昂貴初始化延後到首次使用或安全的背景階段，並避免重複取得相同物件與部署資訊。
- 將啟動註冊拆成可個別量測、可獨立驗證且具冪等保護的初始化單元，維持既有新竹／高雄模式、權限與 UI 行為。
- 加入載入效能回歸驗證與功能驗證，留下基準、改善後結果及可接受門檻；若延後初始化失敗，需可診斷且不得使主程式載入失敗。

## Capabilities

### New Capabilities

- `module-load-performance`: 定義模組載入的分段量測、關鍵路徑最佳化、延後初始化可靠性與效能回歸驗證。

### Modified Capabilities

無。

## Impact

- 主要影響 `Program.cs` 的 `Main()`、`DeployModeSetup()` 與各項功能註冊流程。
- 可能新增輕量級載入計時／診斷輔助類別，以及延後初始化的協調與冪等保護。
- 需驗證 `Student`、`EduAdmin` Ribbon、ACL、三個學生明細項目、學期歷程功能與資料合理性檢查仍完整註冊。
- 不變更公開 API、資料格式、成績計算規則或使用者操作流程；不新增外部套件相依。
